    API keys, tokens and codes¶

    Passwords, API keys stored as digests, revoked tokens, one-time codes, the second factor (TOTP), passkeys (WebAuthn) and step-up. In fastapi_alcazaba.auth.

    In the guide: Passwords, API keys, Revoked tokens and one-time codes, Second factor, Passkeys. In an app: the example, the passwords', the second factor's.

    fastapi_alcazaba.auth.FastAPIPasswords ¶

    FastAPIPasswords(*, parameters: ScryptParameters | None = None, pepper: str | SecretStr | None = None, min_length: int = 15, max_attempts: int = 10, lockout: int = 900, reset_ttl: int = 3600, strength: PasswordStrength | None = None, blocklist: PasswordBlocklist | None = None, pwned: PwnedPasswords | None = None, cache: Cache | None = None, namespace: str = 'passwords', audit: FastAPIAudit | None = None)

    Passwords, from sign-up to reset.

    • Hashes: scrypt with a random salt each, in a thread (it takes a fifth of a second on purpose); with a pepper, the password is first an HMAC of it, so that a stolen database without the pepper gives nothing to guess against.
    • Guesses: after max_attempts wrong passwords for an account, its logins are refused for lockout seconds, the right password too; the attempts of other accounts aren't affected. Put a rate limit per client on the login route too, for one client trying many accounts.
    • Unknown accounts take as long as known ones: verify hashes against a made-up hash.
    • New passwords: evaluate says what's wrong with one, as NIST SP 800-63B says: too short or long, made of the user's data, and with each check set up, in the app's blocklist (PasswordBlocklist), too easy to guess (strength, PasswordStrength), or among those leaked, which attackers try first (pwned, PwnedPasswords).
    • Resets: reset_token makes a random token, kept as a digest for reset_ttl seconds, that use_reset_token turns into its user once; a new one replaces the user's last.

    Name Type Description Default
    parameters ScryptParameters | None

    scrypt's cost.

    		 None
    pepper str | SecretStr | None

    a secret of 32 bytes or more, kept out of the database (your settings). It can't be rotated without the passwords: keep it.

    		 None
    min_length int

    characters a new password needs (NIST SP 800-63B: 15 when the password is the only factor, 8 with another).

    		 15
    max_attempts int

    wrong passwords per account before the lockout.

    		 10

    seconds an account's logins are refused after them.

    		 900
    reset_ttl int

    seconds a reset token lasts.

    		 3600
    strength PasswordStrength | None

    refuses new passwords zxcvbn scores below its min_score; None for no check.

    		 None
    blocklist PasswordBlocklist | None

    refuses new passwords in it; None for no check.

    		 None
    pwned PwnedPasswords | None

    refuses new passwords among those leaked; None for no check (and no call).

    		 None

    the Cache whose backend keeps the attempts and the reset tokens; FastAPICache's by default.

    		 None

    part of the keys, after the cache's prefix (see Cache.state_key).

    		 'passwords'

    		 None

    hash async ¶

    hash(password: str) -> str

    The hash of password to store, in PHC's format. Raises ValueError for a password longer than MAX_PASSWORD: check tells it first.

    needs_rehash ¶

    needs_rehash(stored: str) -> bool

    Whether stored was made with other parameters: hash the password again at the next login, when it's at hand.

    verify async ¶

    verify(user_id: Any, password: str, stored: str | None, *, request: HTTPConnection | None = None) -> bool

    Whether password is the one of stored, the hash of user_id's. False when it isn't, when the account is locked out by wrong ones, or when the backend fails. For an account that doesn't exist, stored=None (and its user_id, or None): it takes as long as one that does.

    evaluate async ¶

    evaluate(password: str, *, user_inputs: Sequence[str] = ()) -> PasswordCheck

    What's wrong with password as a new one, as NIST SP 800-63B says, and what was checked. Its problems, in PROBLEMS' order:

    • "too_short" (fewer than min_length characters), "too_long" (more than MAX_PASSWORD);
    • "invalid_characters": a lone surrogate, which JSON lets through but no text holds;
    • "contains_user_input": one of user_inputs (the username, the name, the e-mail address or its local part) or one of their words, of 4 characters or more, is in it, whatever its case and accents;
    • "blocklisted": in blocklist;
    • "weak": strength scores it below its min_score;
    • "pwned": among those leaked, asked only when there's no other problem.

    No rule on its characters (a digit, a capital): length is what makes it strong. Never raises for a str, but BackendUnavailable from a PwnedPasswords that fails closed.

    check async ¶

    check(password: str, *, user_inputs: Sequence[str] = ()) -> list[str]

    The problems evaluate finds with password as a new one; an empty list when it's fine.

    reset_token async ¶

    reset_token(user_id: Any) -> str

    A token for user_id to set a new password, for the link of the e-mail it's sent by; it replaces their last one. Raises BackendUnavailable when the backend fails.

    use_reset_token async ¶

    use_reset_token(token: str, *, request: HTTPConnection | None = None) -> str | None

    The user ID (as a string) whose token it is, used up; None when it's unknown, expired, used, or replaced by a newer one. Then set the new password, and end the user's sessions (UserSessions.end_all).

    fastapi_alcazaba.auth.PasswordStrength ¶

    PasswordStrength(*, min_score: int = 3)

    How hard a password is to guess, by zxcvbn: it finds dictionary words, names, keyboard walks, dates, repeats, sequences and l33t substitutions, and the user's own data, and scores the guesses they'd take from 0 to 4. Needs zxcvbn: the password-strength extra.

    zxcvbn measures 72 characters at most: a longer password has its first 72 scored. It takes a millisecond or so, up to some tens: FastAPIPasswords runs it in a thread.

    Parameters:

    Name Type Description Default
    min_score int

    the lowest score accepted: 3 by default ("safely unguessable", 10^10 guesses), 4 for accounts that matter more, 2 at the least.

    		 3

    measure ¶

    measure(password: str, *, user_inputs: Sequence[str] = ()) -> tuple[int, tuple[str, ...]]

    password's score, 0 to 4, and zxcvbn's advice (a warning and suggestions, empty for a good one). user_inputs, such as the user's name and e-mail address, count as words an attacker knows, with their words, and without accents too. Blocks for its time: in a coroutine, run it in a thread.

    fastapi_alcazaba.auth.PasswordBlocklist ¶

    PasswordBlocklist(passwords: Iterable[str])

    Passwords refused whatever their strength: the app's name, its products, a list of common ones. Built once, at start-up, and kept in memory (a hundred bytes or so per entry: for lists of millions, PwnedPasswords).

    Entries and passwords are compared normalized (NFKC, casefolded, without spaces around), so that "Acme2024", "ACME2024 " and its fullwidth form are the same; the password that's hashed is still the one sent. Only whole passwords match: zxcvbn finds those that hold a word.

    Parameters:

    Name Type Description Default
    passwords Iterable[str]

    the entries; blank ones are skipped.

    		 required

    fastapi_alcazaba.auth.PwnedPasswords ¶

    PwnedPasswords(*, timeout: float = 2.0, fail_open: bool = True, client: Any = None, url: str = 'https://api.pwnedpasswords.com/range/')

    Whether a password is among those leaked, by Have I Been Pwned's Pwned Passwords API, without sending it: only the first five characters of its SHA-1 go out (k-anonymity), and the answer is padded, so that its size doesn't tell them either. Needs httpx2: the passwords extra.

    When the API doesn't answer in timeout, answers an error, or answers something that isn't a range answer, the check is unavailable: with fail_open the password is taken as not leaked and a warning logged (with the error's class only: never the password, its hash or the prefix); without it, BackendUnavailable is raised.

    Parameters:

    Name Type Description Default
    timeout float

    seconds for the call.

    		 2.0
    fail_open bool

    when the check is unavailable, accept the password (the default: the check is advice, and a sign-up mustn't wait for a third party), or raise BackendUnavailable (for apps that would rather answer a 503 than take a password unchecked).

    		 True
    client Any

    the httpx2 client to call it with; one of its own by default.

    		 None
    url str

    the API's range endpoint.

    		 'https://api.pwnedpasswords.com/range/'

    fastapi_alcazaba.auth.FastAPIAPIKeys ¶

    FastAPIAPIKeys(lookup: Lookup[R], *, header: str = 'X-API-Key', prefix: str = 'ak', bearer: bool = False, pepper: Secrets | None = None, cache_ttl: float = 0.0, cache_size: int = 1024, scheme_name: str = 'APIKey', metrics: Metrics | None = None)

    Bases: Generic[R]

    FastAPI dependency that authenticates a request by its API key and returns its record.

    keys = FastAPIAPIKeys(load_key, pepper=settings.api_key_pepper)

@app.get("/me")
async def me(key: Annotated[StoredKey, Depends(keys)]) -> ...

@app.delete("/orders/{id}", dependencies=[Depends(keys.require("orders:write"))])

    The key comes in the header (X-API-Key by default) or, with bearer=True, as Authorization: Bearer <key>; both appear in the OpenAPI schema, for the docs' Authorize button. A missing, malformed, unknown, wrong or expired key gets the same 401 (with WWW-Authenticate); a valid key without a scope that require asks for gets a 403. Keys and secrets are never logged; put a FastAPIRateLimiter in front, since each request with a well-formed key costs a lookup.

    Revoking a key: delete its record, or set its expires_at to the past. With cache_ttl, records are kept in each process for that many seconds, so a revocation takes up to that long to reach every process.

    Parameters:

    Name Type Description Default
    lookup Lookup[R]

    lookup(key_id): the stored record of that id, or None. Async, or a plain function, which runs in a thread like FastAPI's sync dependencies.

    		 required
    header str

    the request header holding the key.

    		 'X-API-Key'
    prefix str

    the start of every key (ak_...): letters, digits and underscores, starting with a letter. Secret scanners (GitHub's, GitLab's) can be taught to spot it, and to check its checksum.

    		 'ak'
    bearer bool

    also accept the key as Authorization: Bearer <key>.

    		 False
    pepper Secrets | None

    records kept at most per process (the least recently used are dropped).

    		 1024
    scheme_name str

    name of the scheme in the OpenAPI schema.

    		 'APIKey'
    metrics Metrics | None

    where to count the outcomes (fastapi_alcazaba.api_keys); FastAPICache's by default.

    		 None

    fastapi_alcazaba.auth.TokenBlocklist ¶

    TokenBlocklist(cache: Cache | None = None, *, namespace: str = 'revoked', fail_open: bool = False, leeway: int = 60)

    Revoked tokens (by their jti), sessions (by their sid: every token of one login, see RefreshTokens) and subjects logged out everywhere (revoke_subject).

    blocklist = TokenBlocklist()

async def current_user(claims: Annotated[dict[str, Any], Depends(decode_jwt)]) -> str:
    sub, iat = claims["sub"], claims["iat"]
    if await blocklist.is_revoked(claims["jti"], subject=sub, issued_at=iat):
        raise HTTPException(401)
    return sub

    Each mark lasts while the token could still be accepted, leeway included, and then the backend drops it. When the cache has a signing_key or encryption_key, the marks are sealed with it and planted ones are ignored; but whoever can delete keys in the backend can still un-revoke tokens, so keep it out of reach.

    Parameters:

    Name Type Description Default
    cache Cache | None

    the Cache whose backend keeps the marks; FastAPICache's by default, resolved at each call (so the blocklist can be created before FastAPICache.init).

    		 None
    namespace str

    part of the keys, after the cache's prefix (see Cache.state_key).

    		 'revoked'
    fail_open bool

    when the backend fails, is_revoked answers False (tokens are accepted) instead of True (refused, the default).

    		 False
    leeway int

    seconds your JWT library still accepts a token after its exp (PyJWT's leeway): marks are kept that much longer.

    		 60

    revoke async ¶

    revoke(token_id: str, *, expires_at: Moment | None = None, ttl: int | None = None) -> None

    Refuse the token token_id (its jti) until it would have expired anyway: give its exp as expires_at, or the seconds it has left as ttl. Raises BackendUnavailable when the backend fails: the token isn't revoked then.

    revoke_subject async ¶

    revoke_subject(subject: str, *, ttl: int) -> None

    Refuse every token of subject issued before the current second: log out everywhere, e.g. after a password change. ttl is the longest lifetime of your tokens. iat has whole seconds, so the tokens issued during this second stay valid, among them the one you issue right after for the current session. Raises BackendUnavailable when the backend fails.

    revoke_session async ¶

    revoke_session(session: str, *, ttl: int) -> None

    Refuse every token whose sid is session (one login, on one device), for ttl seconds: the longest lifetime of its tokens. Raises BackendUnavailable when the backend fails.

    is_revoked async ¶

    is_revoked(token_id: str, *, subject: str | None = None, issued_at: Moment | None = None, session: str | None = None) -> bool

    Whether the token is refused: its jti was revoked, its session (sid, give it as session) was, or its subject was logged out everywhere after it was issued (give its sub and iat). When the backend fails, not fail_open.

    fastapi_alcazaba.auth.OneTimeCodes ¶

    OneTimeCodes(secret: Secrets, cache: Cache | None = None, *, digits: int = 6, ttl: int = 300, max_attempts: int = 5, namespace: str = 'otp')

    Codes of digits digits, sent by e-mail or SMS, that prove who someone is: each lasts ttl seconds, works once, and subject has max_attempts guesses for each ttl seconds, whatever the number of codes issued.

    codes = OneTimeCodes(secret=settings.otp_secret)

code = await codes.issue(user.email, purpose="login")  # send it to the user
...
if not await codes.verify(form.email, form.code, purpose="login"):
    raise HTTPException(400, "Invalid or expired code")

    The backend holds an HMAC of each code with secret, never the code: a plain digest of a 6-digit code is brute-forced in milliseconds by whoever reads the backend. Issuing a code replaces the previous one, but doesn't give the guesses back: asking for code after code doesn't add up to more than max_attempts guesses each ttl seconds. Once they're used, the subject waits for the window to end (up to ttl seconds), new codes included; the right code starts the count again. Still put a FastAPIRateLimiter on the route that issues them: each code sent costs an e-mail or an SMS.

    Parameters:

    Name Type Description Default
    secret Secrets

    at least 32 bytes (secrets.token_urlsafe(32)), from the environment or a secret manager. A list rotates them: the first one is used, all of them are accepted.

    		 required
    cache Cache | None

    the Cache whose backend keeps the codes; FastAPICache's by default, resolved at each call.

    		 None
    digits int

    length of the codes, 4 to 10.

    		 6
    ttl int

    seconds each code lasts.

    		 300
    max_attempts int

    guesses allowed for each subject and purpose in ttl seconds, right or wrong, across the codes issued.

    		 5
    namespace str

    part of the keys, after the cache's prefix (see Cache.state_key).

    		 'otp'

    issue async ¶

    issue(subject: str, purpose: str = '') -> str

    A new code for subject (an e-mail address, a user id...) and purpose ("login", "reset-password"...), replacing the previous one; the guesses already made still count. Raises BackendUnavailable when the backend fails.

    verify async ¶

    verify(subject: str, code: str, purpose: str = '') -> bool

    Whether code is the current code of subject for purpose; it's used up then. Of several requests with the right code at the same time, only one gets True. False when the backend fails.

    fastapi_alcazaba.auth.FastAPITOTP ¶

    FastAPITOTP(*, issuer: str, secret: Secrets, cache: Cache | None = None, digits: int = 6, period: int = 30, window: int = 1, algorithm: Algorithm = 'SHA1', max_attempts: int = 5, lockout: int = 900, namespace: str = 'totp', audit: FastAPIAudit | None = None)

    The codes of authenticator apps as a second factor (RFC 6238), recovery codes, and step-up for the routes that need a recent one.

    • The secrets are sealed with AES-256-GCM, each for its user: store sealed, never the secret. A sealed secret copied to another user doesn't open, nor without secret.
    • A code is accepted within window steps of period seconds before or after now, for clocks out of step; each one once (RFC 6238, 5.2): another request with the same code, from someone who looked over the user's shoulder, is refused.
    • Guesses: after max_attempts wrong codes (recovery codes included), the user's codes are refused for lockout seconds, whatever they are: a 6-digit code isn't guessed.
    • When the backend fails, nothing is accepted: no code is checked for replay, nor guesses counted.

    fastapi_alcazaba.auth.FastAPIWebAuthn ¶

    FastAPIWebAuthn(*, rp_id: str, rp_name: str, origins: Collection[str], user_verification: UserVerification = 'required', algorithms: Sequence[int] = (ES256, EDDSA, RS256), timeout: int = 300, cache: Cache | None = None, namespace: str = 'webauthn', audit: FastAPIAudit | None = None)

    Passkeys and security keys: registering them (registration_options, verify_registration) and logging in with them (authentication_options, verify_authentication), as WebAuthn Level 2 says.

    • The challenges are random (32 bytes), kept in the cache's backend for timeout seconds, bound to the ceremony and to the user they were made for, and used once: of two answers to the same challenge, one is checked.
    • The origin of the answer must be one of origins, never in a cross-origin iframe, and the authenticator's data must be for rp_id: a phishing site's origin is refused, and so is its RP ID, which the browser wouldn't sign for another site.
    • The user must be present (a touch), and verified (a PIN, a fingerprint, the phone's lock) with user_verification="required", the default: a passkey is then both factors.
    • The counter: a credential whose counter goes back (or doesn't move, for those that count) was cloned: refused. Synced passkeys count 0, and aren't checked.
    • When the backend fails, no answer is checked: the challenges can't be used once.

    Parameters:

    Name Type Description Default
    rp_id str

    the relying party's ID: the site's domain, or one it's under (example.com for https://login.example.com). The credentials only work there.

    		 required
    rp_name str

    the name the authenticator shows ("Example").

    		 required
    origins Collection[str]

    the origins the answers come from, https://example.com (or http://localhost:8000, in development); each on rp_id or under it.

    		 required
    user_verification UserVerification

    required, preferred or discouraged.

    		 'required'
    algorithms Sequence[int]

    the COSE algorithms accepted, in order of preference.

    		 (ES256, EDDSA, RS256)
    timeout int

    seconds a challenge lasts, and the browser waits for the user.

    		 300
    cache Cache | None

    the Cache whose backend keeps the challenges; FastAPICache's by default.

    		 None
    namespace str

    part of the keys, after the cache's prefix (see Cache.state_key).

    		 'webauthn'
    audit FastAPIAudit | None

    the audit trail that records each passkey registered (auth.passkey.register) and each login with one (auth.passkey), with their outcome.

    		 None

    fastapi_alcazaba.auth.stepup.require_recent ¶

    require_recent(user_id: Callable[..., Any], max_age: int = 300, *, methods: Collection[str] | None = None, claims: Callable[..., Any] | None = None, acr_values: Collection[str] | None = None, subject: Callable[[dict[str, Any]], Any] | None = None, audit: FastAPIAudit | None = None) -> Callable[..., Any]

    A dependency that lets through the users who authenticated in the last max_age seconds, with one of methods when given, and returns their ID; requests without a user get a 401.

    • Sessions: the session's mark (mark) must be this user's, recent, and of one of methods ("passkey", "totp"...). Otherwise a 403 problem (PROBLEM_TYPE, "Second factor required") with max_age and methods, for the front end to ask for one and mark it.
    • Tokens: when claims (a dependency) gives the request's token claims (a dict), they decide instead: the token must be the user's (its sub is user_id's), with auth_time within max_age, an amr among methods (RFC 8176's names: "hwk", "otp", "mfa"...), an acr among acr_values. Otherwise a 401 with WWW-Authenticate: Bearer error="insufficient_user_authentication" and the max_age and acr_values to ask the provider for (RFC 9470), as a problem too.
    • Audited: with audit, each check is an auth.stepup event with the method and the age (and the reason when it's refused).

    Parameters:

    Name Type Description Default
    user_id Callable[..., Any]

    a dependency that returns the request's user ID, or None.

    		 required
    claims Callable[..., Any] | None

    a dependency that returns the token's claims when the request came with one (auth.authenticate("jwt", optional=True)), None for a session.

    		 None
    subject Callable[[dict[str, Any]], Any] | None

    the user ID a token's claims belong to, compared with user_id's; the sub claim by default. A token of someone else (a fresh one of the attacker's own, sent with a stolen session) never steps anybody up.

    		 None
