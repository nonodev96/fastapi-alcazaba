    API keys, tokens and codes¶

    API keys stored as digests, revoked tokens and one-time codes. In fastapi_alcazaba.auth.

    In the guide: API keys, Revoked tokens and one-time codes. In an app: the example.

    fastapi_alcazaba.auth.FastAPIAPIKeys ¶

    FastAPIAPIKeys(lookup: Lookup[R], *, header: str = 'X-API-Key', prefix: str = 'ak', bearer: bool = False, pepper: Secrets | None = None, cache_ttl: float = 0.0, cache_size: int = 1024, scheme_name: str = 'APIKey', metrics: Metrics | None = None)

    Bases: Generic[R]

    FastAPI dependency that authenticates a request by its API key and returns its record.

    keys = FastAPIAPIKeys(load_key, pepper=settings.api_key_pepper)

@app.get("/me")
async def me(key: Annotated[StoredKey, Depends(keys)]) -> ...

@app.delete("/orders/{id}", dependencies=[Depends(keys.require("orders:write"))])

    The key comes in the header (X-API-Key by default) or, with bearer=True, as Authorization: Bearer <key>; both appear in the OpenAPI schema, for the docs' Authorize button. A missing, malformed, unknown, wrong or expired key gets the same 401 (with WWW-Authenticate); a valid key without a scope that require asks for gets a 403. Keys and secrets are never logged; put a FastAPIRateLimiter in front, since each request with a well-formed key costs a lookup.

    Revoking a key: delete its record, or set its expires_at to the past. With cache_ttl, records are kept in each process for that many seconds, so a revocation takes up to that long to reach every process.

    Parameters:

    Name Type Description Default
    lookup Lookup[R]

    lookup(key_id): the stored record of that id, or None. Async, or a plain function, which runs in a thread like FastAPI's sync dependencies.

    		 required
    header str

    the request header holding the key.

    		 'X-API-Key'
    prefix str

    the start of every key (ak_...): letters, digits and underscores, starting with a letter. Secret scanners (GitHub's, GitLab's) can be taught to spot it.

    		 'ak'
    bearer bool

    also accept the key as Authorization: Bearer <key>.

    		 False
    pepper Secrets | None

    a server secret (at least 32 bytes) mixed into every digest, kept out of the database (an environment variable, a secret manager). A list rotates it: the first one is used for new keys, all of them are accepted; old peppers must stay as long as keys made with them do. Changing it without keeping the old one invalidates every key.

    		 None
    cache_ttl float

    seconds each process keeps a record it looked up; 0 looks up every request.

    		 0.0
    cache_size int

    records kept at most per process (the least recently used are dropped).

    		 1024
    scheme_name str

    name of the scheme in the OpenAPI schema.

    		 'APIKey'
    metrics Metrics | None

    where to count the outcomes (fastapi_alcazaba.api_keys); FastAPICache's by default.

    		 None

    require ¶

    require(*scopes: str) -> Callable[..., Awaitable[R]]

    A dependency like this one that also needs every scope in scopes (a 403 without them): Depends(keys.require("orders:write")).

    generate ¶

    generate(*, scopes: Iterable[str] = (), expires_at: datetime | None = None) -> NewAPIKey

    A new key, to show its owner once, and its record, to store. scopes are free-form names ("orders:read"); expires_at a datetime with its time zone.

    authenticate async ¶

    authenticate(key: str | None) -> R

    The record of key, if it's valid; raises an HTTPException (401) otherwise. For keys that come some other way (a WebSocket message, a test).

    forget ¶

    forget(key_id: str | None = None) -> None

    Drop the record of key_id (every record when None) from this process's cache: call it after revoking a key, for this process to see it at once.

    fastapi_alcazaba.auth.APIKeyRecord dataclass ¶

    APIKeyRecord(id: str, digest: str, scopes: frozenset[str] = frozenset(), expires_at: datetime | None = None)

    What to store for a key: everything but the key itself.

    fastapi_alcazaba.auth.TokenBlocklist ¶

    TokenBlocklist(cache: Cache | None = None, *, namespace: str = 'revoked', fail_open: bool = False, leeway: int = 60)

    Revoked tokens (by their jti) and subjects logged out everywhere (revoke_subject).

    blocklist = TokenBlocklist()

async def current_user(claims: Annotated[dict[str, Any], Depends(decode_jwt)]) -> str:
    sub, iat = claims["sub"], claims["iat"]
    if await blocklist.is_revoked(claims["jti"], subject=sub, issued_at=iat):
        raise HTTPException(401)
    return sub

    Each mark lasts while the token could still be accepted, leeway included, and then the backend drops it. When the cache has a signing_key or encryption_key, the marks are sealed with it and planted ones are ignored; but whoever can delete keys in the backend can still un-revoke tokens, so keep it out of reach.

    Parameters:

    Name Type Description Default
    cache Cache | None

    the Cache whose backend keeps the marks; FastAPICache's by default, resolved at each call (so the blocklist can be created before FastAPICache.init).

    		 None
    namespace str

    part of the keys, after the cache's prefix (see Cache.state_key).

    		 'revoked'
    fail_open bool

    when the backend fails, is_revoked answers False (tokens are accepted) instead of True (refused, the default).

    		 False
    leeway int

    seconds your JWT library still accepts a token after its exp (PyJWT's leeway): marks are kept that much longer.

    		 60

    revoke async ¶

    revoke(token_id: str, *, expires_at: Moment | None = None, ttl: int | None = None) -> None

    Refuse the token token_id (its jti) until it would have expired anyway: give its exp as expires_at, or the seconds it has left as ttl. Raises BackendUnavailable when the backend fails: the token isn't revoked then.

    revoke_subject async ¶

    revoke_subject(subject: str, *, ttl: int) -> None

    Refuse every token of subject issued before the current second: log out everywhere, e.g. after a password change. ttl is the longest lifetime of your tokens. iat has whole seconds, so the tokens issued during this second stay valid, among them the one you issue right after for the current session. Raises BackendUnavailable when the backend fails.

    is_revoked async ¶

    is_revoked(token_id: str, *, subject: str | None = None, issued_at: Moment | None = None) -> bool

    Whether the token is refused: its jti was revoked, or its subject was logged out everywhere after it was issued (give its sub and iat). When the backend fails, not fail_open.

    fastapi_alcazaba.auth.OneTimeCodes ¶

    OneTimeCodes(secret: Secrets, cache: Cache | None = None, *, digits: int = 6, ttl: int = 300, max_attempts: int = 5, namespace: str = 'otp')

    Codes of digits digits, sent by e-mail or SMS, that prove who someone is: each lasts ttl seconds, works once and is lost after max_attempts wrong guesses.

    codes = OneTimeCodes(secret=settings.otp_secret)

code = await codes.issue(user.email, purpose="login")  # send it to the user
...
if not await codes.verify(form.email, form.code, purpose="login"):
    raise HTTPException(400, "Invalid or expired code")

    The backend holds an HMAC of each code with secret, never the code: a plain digest of a 6-digit code is brute-forced in milliseconds by whoever reads the backend. Issuing a code replaces the previous one and gives max_attempts again, so put a FastAPIRateLimiter on the route that issues them.

    Parameters:

    Name Type Description Default
    secret Secrets

    at least 32 bytes (secrets.token_urlsafe(32)), from the environment or a secret manager. A list rotates them: the first one is used, all of them are accepted.

    		 required
    cache Cache | None

    the Cache whose backend keeps the codes; FastAPICache's by default, resolved at each call.

    		 None
    digits int

    length of the codes, 4 to 10.

    		 6
    ttl int

    seconds each code lasts.

    		 300
    max_attempts int

    guesses allowed for each code, right or wrong.

    		 5
    namespace str

    part of the keys, after the cache's prefix (see Cache.state_key).

    		 'otp'

    issue async ¶

    issue(subject: str, purpose: str = '') -> str

    A new code for subject (an e-mail address, a user id...) and purpose ("login", "reset-password"...), replacing the previous one. Raises BackendUnavailable when the backend fails.

    verify async ¶

    verify(subject: str, code: str, purpose: str = '') -> bool

    Whether code is the current code of subject for purpose; it's used up then. Of several requests with the right code at the same time, only one gets True. False when the backend fails.
