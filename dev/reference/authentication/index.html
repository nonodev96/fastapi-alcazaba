    Authentication strategies¶

    FastAPIAuth and its strategies. In fastapi_alcazaba.auth; JWTStrategy, OAuth2Strategy, OIDCStrategy, SAMLStrategy and UnkeyStrategy in fastapi_alcazaba.auth.strategies.jwt, .oauth2, .oidc, .saml and .unkey, with their extras.

    In the guide: Strategies. In an app: the example.

    fastapi_alcazaba.auth.FastAPIAuth ¶

    FastAPIAuth(*strategies: Strategy, metrics: Metrics | None = None, audit: FastAPIAudit | None = None, actor: Actor | None = None)

    The strategies of an app, and the dependencies that authenticate with them.

    auth = FastAPIAuth(JWTStrategy(...), SessionStrategy(...))

@app.get("/me")
async def me(user: Annotated[User, Depends(auth.authenticate("jwt", "session"))]): ...

    A request is authenticated once: the dependencies of a route that ask for the same strategies get the user the first one found (an API key isn't verified twice).

    Parameters:

    Name Type Description Default
    strategies Strategy

    the strategies, by their names; more with use.

    		 ()
    metrics Metrics | None

    where to count the outcomes (fastapi_alcazaba.auth); FastAPICache's by default.

    		 None
    audit FastAPIAudit | None

    the audit trail that records the failed authentications (auth.failure), the logins of OAuth2, OpenID Connect and SAML (auth.login) and the requests without a scope they need (auth.scope), with the request's route and client; not every request authenticated.

    		 None
    actor Actor | None

    who the user a strategy found is, in those events: actor(user), an ID. By default the user itself when it's an ID, else its sub or id.

    		 None

    use ¶

    use(strategy: S) -> S

    Add a strategy, under its name; returns it, with its own type (github.redirect()).

    authenticate ¶

    authenticate(*names: str, optional: bool = False, scopes: Collection[str] = ()) -> Callable[..., Awaitable[Any]]

    A dependency that returns the user of the first of these strategies that finds one (all of them, in the order they were added, without names). Without one, a 401 with their challenges (a WebSocket is closed with 1008), or None when optional.

    The user's credentials must grant scopes, and those of Security(dependency, scopes=[...]) where it's used (FastAPI's, which the OpenAPI schema shows); one missing is a 403 with WWW-Authenticate: Bearer error="insufficient_scope".

    The user of the first of these strategies (all of them without names) that finds one; None when none does. For connections that don't go through a dependency.

    fastapi_alcazaba.auth.strategies.jwt.JWTStrategy ¶

    JWTStrategy(key: Secrets | None = None, *, keys: Sequence[JWTKey] | None = None, jwks_url: str | None = None, algorithms: Sequence[str] | None = None, audience: str | None = None, issuer: str | None = None, leeway: float = 0, required: Sequence[str] = ('exp', 'sub'), verify: Callable[[dict[str, Any]], Any] | None = None, blocklist: TokenBlocklist | None = None, cookie: str | None = None, jwks_lifespan: float = 300, jwks_stale: float = 3600, jwks_timeout: float = 3.0, jwks_client: Any = None, token_type: str | None = None, scope_claims: Sequence[str] = ('scope', 'scp'), name: str = 'jwt')

    Bases: Strategy

    Authenticates by a JWT in Authorization: Bearer <token> (or a cookie), verified with the app's keys or the provider's JWKS. The signature, exp, nbf and the claims of required are always checked, aud and iss when given; a token with an aud is refused when no audience is, as it's meant for some other service. alg: none is never accepted, and each key verifies with its own algorithm only.

    Only access tokens: the provider signs its ID tokens and logout tokens with the same keys, often for the same aud, and those travel through less guarded places (a logout URL, the browser). A token with a header typ other than JWT or at+jwt (logout+jwt...), with a nonce (an ID token) or events (a logout token, a security event), or whose typ claim is Keycloak's ID, Logout or Refresh, is refused.

    Give one of keys, key and jwks_url.

    Parameters:

    Name Type Description Default
    key Secrets | None

    what verifies the tokens: a secret of at least 32 bytes for HS256, HS384 and HS512 (a list rotates them: the first one signs, all of them verify), or a public key (PEM) for RS256, ES256, EdDSA... keys does this for keys of any type.

    		 None
    keys Sequence[JWTKey] | None

    JWTKeys, each with its algorithm: the first one signs (when it can) and doesn't retire, all of them verify, until their until. HMAC and asymmetric keys may be mixed (from HS256 to RS256). A token is verified with the key its kid names; one without a kid, or with one no key has (another issuer's own ids), with the keys whose kid wasn't given.

    		 None
    jwks_url str | None

    the provider's JWKS (HTTPS) instead of keys: its keys are fetched, by the kid of each token, and kept for jwks_lifespan seconds; a kid it doesn't have makes it fetched again, at most every 30 seconds. Needs audience and issuer: the provider signs the tokens of every app it serves with the same keys.

    		 None
    algorithms Sequence[str] | None

    those accepted. With key, the first one signs (HS256 by default); with jwks_url, asymmetric ones (RS256, ES256, PS256 and EdDSA by default). Not with keys.

    		 None
    audience str | None

    the aud the tokens must have.

    		 None
    issuer str | None

    the iss the tokens must have.

    		 None
    leeway float

    seconds of tolerance on exp and nbf, for clocks out of step; the blocklist's leeway must be at least as long.

    		 0
    required Sequence[str]

    claims a token must have.

    		 ('exp', 'sub')
    verify Callable[[dict[str, Any]], Any] | None

    verify(claims): the user, or None to refuse the token. Async, or a plain function, which runs in a thread. By default the user is the claims themselves.

    		 None
    blocklist TokenBlocklist | None

    refuses the tokens revoked there (by jti, by sid for one login, and by sub and iat for "log out everywhere"); tokens then need a jti and an iat.

    		 None
    cookie str | None

    also reads the token from this cookie, for browsers.

    		 None
    jwks_lifespan float

    seconds the provider's keys are kept before they're fetched again.

    		 300
    jwks_stale float

    seconds more they're used while the JWKS can't be fetched; then the requests get a 503 until it can.

    		 3600
    jwks_timeout float

    seconds for the whole fetch of the JWKS.

    		 3.0
    jwks_client Any

    the httpx2 client to fetch the JWKS with; one of its own by default, with a deadline and a circuit breaker (ResilientTransport), closed by aclose().

    		 None
    token_type str | None

    the header typ every token must have ("at+jwt", RFC 9068's), for a provider that sets it; any of JWT, at+jwt or none by default.

    		 None
    scope_claims Sequence[str]

    the claims whose scopes the token grants, for the routes that need some (Security(..., scopes=[...])): RFC 9068's scope, a string of them separated by spaces, and scp, a list (Entra ID, Okta); permissions for Auth0's.

    		 ('scope', 'scp')
    name str

    what FastAPIAuth.authenticate calls it by.

    		 'jwt'

    fastapi_alcazaba.auth.strategies.jwt.JWKSUnavailable ¶

    Bases: Exception

    The provider's keys can't be had: its JWKS didn't answer (or not with keys) and those fetched before are too old. JWTStrategy refuses the request with a 503.

    fastapi_alcazaba.auth.strategies.oauth2.OAuth2Strategy ¶

    OAuth2Strategy(*, name: str, authorization_url: str, token_url: str, client_id: str, client_secret: str | SecretStr, redirect_uri: str, scopes: Sequence[str] = (), userinfo_url: str | None = None, verify: Callable[[dict[str, Any], dict[str, Any] | None], Any] | None = None, client_auth: Literal['basic', 'post'] = 'basic', params: Mapping[str, str] | None = None, secure: bool = True, timeout: float = 10.0, client: Any = None)

    Bases: AuthorizationCodeFlow

    Authenticates the requests that come back from the provider's login page (the callback): checks their state, exchanges their code for tokens, reads the user's profile, and returns the user that verify makes of them. Other requests carry nothing for it (None): it only goes on the callback route.

    redirect() starts the login: it sends the browser to the provider with a random state and a PKCE challenge, whose verifier waits in a short-lived cookie (HttpOnly, SameSite=Lax, __Host- when Secure). A callback without that cookie or with another state is refused: nobody can log a user in with their own account (login CSRF) nor use a stolen code.

    For OpenID Connect providers, OIDCStrategy also verifies the ID token they send.

    the app's secret at the provider.

    		 required

    fastapi_alcazaba.auth.strategies.oidc.OIDCStrategy ¶

    OIDCStrategy(*, name: str, issuer: str, client_id: str, client_secret: str | SecretStr | None = None, redirect_uri: str, scopes: Sequence[str] = ('openid', 'email', 'profile'), verify: Callable[[dict[str, Any], dict[str, Any] | None], Any] | None = None, userinfo: bool = False, max_age: int | None = None, algorithms: Sequence[str] = ('RS256', 'ES256', 'PS256', 'EdDSA'), leeway: float = 60, authorization_url: str | None = None, token_url: str | None = None, userinfo_url: str | None = None, jwks_url: str | None = None, jwks_lifespan: float = 3600, jwks_stale: float = 3600, client_auth: Literal['basic', 'post', 'private_key_jwt'] = 'basic', client_key: JWTKey | None = None, post_logout_redirect_uris: Sequence[str] = (), end_session_url: str | None = None, params: Mapping[str, str] | None = None, secure: bool = True, timeout: float = 10.0, client: Any = None)

    Bases: AuthorizationCodeFlow

    Authenticates the callback of an OpenID Connect login: exchanges its code for tokens, verifies the ID token, and returns the user that verify makes of its claims.

    The ID token is refused unless it's signed with one of algorithms by a key of the provider's JWKS (never none, never with the client secret), comes from issuer, is meant for this app (aud has client_id, and azp is it when there are several audiences or an azp), hasn't expired (exp) nor was issued in the future (iat), carries the nonce the login sent, the at_hash of the access token when it has one, and an auth_time within max_age when it's set. A provider that sends no ID token is refused.

    Its endpoints and keys come from the issuer's discovery document (/.well-known/openid-configuration), read by await discover() in the lifespan; whose issuer must be issuer exactly. Endpoints given here aren't read from it, and with all of them (authorization_url, token_url, jwks_url) there's nothing to discover.

    The raw ID token of a login is in request.state.id_token once the callback is authenticated: keep it in the session for logout_url(id_token_hint=...). The claims have the provider's session id (sid): keep it as oidc_sid in the session for back-channel logout to find it (UserSessions).

    backchannel_logout_endpoint ¶

    backchannel_logout_endpoint(sessions: UserSessions, *, user_id: Callable[[str], Awaitable[Any] | Any] | None = None, cache: Cache | None = None) -> Callable[[Request], Awaitable[Response]]

    A valid token ends the app's sessions of that login: those whose oidc_sid is its sid (UserSessions.end_sid: keep the ID token's sid there at login), or, for a token with a sub and no sid, every session of the user (end_all). user_id(sub) (sync or async) gives the app's user id of the provider's sub (the sub itself by default; None: nothing to end).     fastapi_alcazaba.auth.strategies.saml.SAMLStrategy ¶

    SAMLStrategy(*, entity_id: str, acs_url: str, idp_entity_id: str, idp_sso_url: str, idp_certificate: str | Sequence[str], verify: Callable[[SAMLProfile], Any] | None = None, name_id_format: str | None = None, clock_skew: float = 60, cache: Cache | None = None, name: str = 'saml')

    Bases: Strategy

    Authenticates the requests the IdP posts to the Assertion Consumer Service (the ACS): checks the signature of their response with the IdP's certificate, and that it answers the login this browser started; the user is what verify makes of the profile. Other requests carry nothing for it (None): it only goes on the ACS route.

    redirect() starts the login (SP-initiated: logins the IdP starts by itself aren't accepted). The id of its request waits in a short-lived cookie (__Host-, HttpOnly, Secure, and SameSite=None: the IdP posts to the ACS from its own site), and the answer must carry it.

    Checked on what the signature covers: the issuer, the audience (entity_id), the recipient (acs_url), the request it answers, when it's valid (with clock_skew), and that it's a bearer assertion. Each assertion works once: its id is kept in the cache's backend until it expires, so a copy is refused by every process. Not supported: encrypted assertions, signed requests, single logout.

    fastapi_alcazaba.auth.strategies.unkey.UnkeyStrategy ¶

    UnkeyStrategy(unkey: UnkeyClient, verify: Callable[[UnkeyKey], Any] | None = None, *, permissions: str | None = None, cost: int = 1, ratelimits: Sequence[str] = (), keyspaces: Sequence[str] = (), tags: Sequence[str] = (), header: str | None = None, credits_status: int = HTTP_429_TOO_MANY_REQUESTS, name: str = 'unkey', metrics: Metrics | None = None)

    Bases: Strategy

    Authenticates by an API key that Unkey verifies: Authorization: Bearer <key> by default, or the header header. Each request is one verification, which spends the key's credits and counts in its rate limits: nothing is cached, so a key deleted or disabled is refused at once (Unkey takes up to 30 seconds to spread a deletion).

    What Unkey answers:

    • VALID: the user is verify(key) (an UnkeyKey), the key itself without verify.
    • NOT_FOUND, DISABLED, EXPIRED: authentication fails (a 401, or the next strategy).
    • INSUFFICIENT_PERMISSIONS, FORBIDDEN: a 403; the key is valid, it may not do this.
    • RATE_LIMITED: a 429 with Retry-After; USAGE_EXCEEDED (no credits left): a 429, or a 402 with credits_status=402.
    • Unkey down, slow (timeout) or limiting the workspace: a 503. A root key without the verify permission: UnkeyError, a 500.

    A route that needs other permissions or costs more credits has a strategy of its own, with another name and the same client: UnkeyStrategy(verifier, name="unkey-admin", permissions="admin.*").

    what the key must have, in Unkey's query syntax: "documents.read AND users.view".
