    Pagination¶

    The twelve strategies, with their parameters and pages. Each strategy in its module of fastapi_alcazaba.pagination, with its parameters and page.

    In the guide: Pagination. In an app: the examples.

    fastapi_alcazaba.pagination.page_number.PaginationPageNumber ¶

    PaginationPageNumber(*, default_page_size: int = 50, max_page_size: int = 100)

    Pagination by page number: ?page=2&page_size=20.

    pages = PaginationPageNumber()

@app.get("/products")
@cache(expire=60)
async def products(
    params: Annotated[PageNumberParams, Depends(pages)],
) -> PageNumberPage[Product]:
    return pages.paginate(rows, params, total=count)

    Parameters:

    Name Type Description Default
    default_page_size int

    items per page when the request doesn't say.

    		 50
    max_page_size int

    the most a request may ask for (a 422 beyond), so that nobody asks for a million rows at once.

    		 100

    params ¶

    params(*, page: int = 1, page_size: int | None = None) -> PageNumberParams

    The parameters of a page, as the dependency gives them (for tests and scripts).

    paginate ¶

    paginate(items: Sequence[T], params: PageNumberParams, *, total: int | None = None) -> PageNumberPage[T]

    The page of items that params asks for. Without total, items is the whole list and the page is sliced from it; with total, items is that page already (queried with params.offset and params.limit). The response links to the first, previous, next and last pages.

    fastapi_alcazaba.pagination.limit_offset.PaginationLimitOffset ¶

    PaginationLimitOffset(*, default_limit: int = 50, max_limit: int = 100)

    Pagination by limit and offset, with the total: ?limit=20&offset=40. Without the total, which takes a count of the whole list: PaginationOffset.

    Parameters:

    Name Type Description Default
    default_limit int

    items per page when the request doesn't say.

    		 50
    max_limit int

    the most a request may ask for (a 422 beyond).

    		 100

    params ¶

    params(*, limit: int | None = None, offset: int = 0) -> LimitOffsetParams

    The parameters of a page, as the dependency gives them (for tests and scripts).

    paginate ¶

    paginate(items: Sequence[T], params: LimitOffsetParams, *, total: int | None = None) -> LimitOffsetPage[T]

    The page of items that params asks for, as PaginationPageNumber.paginate. The first and last pages that the response links to start at multiples of the limit.

    fastapi_alcazaba.pagination.offset.PaginationOffset ¶

    PaginationOffset(*, default_limit: int = 50, max_limit: int = 100)

    Pagination by offset, without the total: ?offset=40&limit=20.

    offsets = PaginationOffset()

@app.get("/logs")
@cache(expire=60)
async def logs(params: Annotated[OffsetParams, Depends(offsets)]) -> OffsetPage[Line]:
    rows = ...  # ORDER BY id LIMIT params.fetch OFFSET params.offset
    return offsets.paginate(rows, params, queried=True)

    The page says whether there's a next one (has_more), from one row more than it holds, instead of counting the whole list: no COUNT(*), which is slow on big tables and outdated as soon as rows are written. With the total and the last page: PaginationLimitOffset.

    Parameters:

    Name Type Description Default
    default_limit int

    items per page when the request doesn't say.

    		 50
    max_limit int

    the most a request may ask for (a 422 beyond).

    		 100

    params ¶

    params(*, offset: int = 0, limit: int | None = None) -> OffsetParams

    The parameters of a page, as the dependency gives them (for tests and scripts).

    paginate ¶

    paginate(items: Sequence[T], params: OffsetParams, *, queried: bool = False) -> OffsetPage[T]

    The page of items that params asks for, linked to the first, previous and next pages.

    Parameters:

    Name Type Description Default
    queried bool

    items is what the database returned for this page: the rows of LIMIT params.fetch OFFSET params.offset, one more than the page when there's a next one. Otherwise items is the whole list, and the page is sliced from it.

    		 False

    fastapi_alcazaba.pagination.ranges.PaginationRange ¶

    PaginationRange(*, default_items: int = 50, max_items: int = 100)

    Pagination by range: ?start=0&end=24, both included.

    ranges = PaginationRange()

@app.get("/contacts")
@cache(expire=60)
async def contacts(params: Annotated[RangeParams, Depends(ranges)]) -> RangePage[Contact]:
    count = ...  # SELECT count(*)
    rows = ...  # ORDER BY name LIMIT params.limit OFFSET params.offset
    return ranges.paginate(rows, params, total=count)

    The response says which items it holds in Content-Range: items 0-24/319 (items */319 when it holds none), on top of the page's start, end and total. A range that ends before it starts, or holds more than max_items items, is a 400; one that starts past the last item a 416, with Content-Range: items */<total>.

    Parameters:

    Name Type Description Default
    default_items int

    items in the range when the request gives no end.

    		 50
    max_items int

    the most a range may hold (a 400 beyond).

    		 100

    params ¶

    params(*, start: int = 0, end: int | None = None) -> RangeParams

    The parameters of a range, as the dependency gives them (for tests and scripts). Raises an HTTPException (400) if end is before start, or the range holds more than max_items items.

    paginate ¶

    paginate(items: Sequence[T], params: RangeParams, *, total: int | None = None) -> RangePage[T]

    The range of items that params asks for. Without total, items is the whole list and the range is sliced from it; with total, items is that range already (queried with params.offset and params.limit). The response links to the first, previous, next and last ranges of the same size. Raises an HTTPException (416) when the range starts past the last item of a list that isn't empty.

    fastapi_alcazaba.pagination.cursor.PaginationCursor ¶

    PaginationCursor(secret: Secrets | None = None, *, default_limit: int = 50, max_limit: int = 100)

    Pagination by cursor: ?limit=20, then ?limit=20&cursor=<next_cursor>.

    cursors = PaginationCursor(secret=settings.cursor_secret)

@app.get("/events")
@cache(expire=60)
async def events(params: Annotated[CursorParams, Depends(cursors)]) -> CursorPage[Event]:
    rows = ...  # WHERE (created_at, id) > params.after ... LIMIT params.fetch
    return cursors.paginate(rows, params, key=lambda e: (e.created_at, e.id), queried=True)

    A cursor is the sort key of a page's last item, base64-encoded: clients can read it, so sort by what they may see. With a secret it's signed too (HMAC-SHA256), and a cursor that a client made or changed gets a 400 like any other invalid one, before the endpoint runs; without it, the values are only checked to be of the types a sort key can have.

    Parameters:

    Name Type Description Default
    secret Secrets | None

    at least 32 bytes (secrets.token_urlsafe(32)); a list rotates them, the first one signing and all of them accepted. None for unsigned cursors.

    		 None
    default_limit int

    items per page when the request doesn't say.

    		 50
    max_limit int

    the most a request may ask for (a 422 beyond).

    		 100

    params ¶

    params(*, cursor: str | None = None, limit: int | None = None) -> CursorParams

    The parameters of a page, with the cursor decoded, as the dependency gives them. Raises an HTTPException (400) if the cursor isn't valid.

    encode ¶

    encode(position: Position) -> str

    The cursor of position.

    decode ¶

    decode(cursor: str) -> Position

    The position cursor points at. Raises an HTTPException (400) if it isn't valid.

    paginate ¶

    paginate(items: Sequence[T], params: CursorParams, *, key: Callable[[T], Position], descending: bool = False, queried: bool = False) -> CursorPage[T]

    The page of items that params asks for.

    Parameters:

    Name Type Description Default
    key Callable[[T], Position]

    an item's sort key: a unique value or tuple ((e.created_at, e.id), not e.created_at alone, which two items may share).

    		 required
    descending bool

    items go from the greatest key to the smallest (newest first).

    		 False
    queried bool

    items is what the database returned for this page: up to params.fetch rows with a key past params.after, in order. Otherwise items is the whole list, sorted by key, and the page is found in it.

    		 False

    fastapi_alcazaba.pagination.keyset.PaginationKeyset ¶

    PaginationKeyset(secret: Secrets | None = None, *, default_limit: int = 50, max_limit: int = 100)

    Pagination by keyset, in both directions: ?limit=20, then ?after=<after> for the next page or ?before=<before> for the one before.

    keyset = PaginationKeyset(secret=settings.keyset_secret)

@app.get("/products")
@cache(expire=60)
async def products(
    params: Annotated[KeysetParams, Depends(keyset)],
) -> KeysetPage[Product]:
    rows = ...  # WHERE (price, id) > params.after ORDER BY price, id LIMIT params.fetch,
    # or WHERE (price, id) < params.before ORDER BY price DESC, id DESC LIMIT params.fetch
    return keyset.paginate(rows, params, key=lambda p: (p.price, p.id), queried=True)

    A key is the sort key of the first or last item of a page, base64-encoded: clients can read it, so sort by what they may see. With a secret it's signed too (HMAC-SHA256), and a key that a client made or changed gets a 400 like any other invalid one, before the endpoint runs; without it, the values are only checked to be of the types a sort key can have.

    Parameters:

    Name Type Description Default
    secret Secrets | None

    at least 32 bytes (secrets.token_urlsafe(32)); a list rotates them, the first one signing and all of them accepted. None for unsigned keys.

    		 None
    default_limit int

    items per page when the request doesn't say.

    		 50
    max_limit int

    the most a request may ask for (a 422 beyond).

    		 100

    params ¶

    params(*, after: str | None = None, before: str | None = None, limit: int | None = None) -> KeysetParams

    The parameters of a page, with its key decoded, as the dependency gives them. Raises an HTTPException (400) if a key isn't valid, or if both are given.

    encode ¶

    encode(position: Position) -> str

    The key of position.

    decode ¶

    decode(key: str, *, name: str = 'after') -> Position

    The position key points at. Raises an HTTPException (400, "Invalid ") if it isn't valid.

    paginate ¶

    paginate(items: Sequence[T], params: KeysetParams, *, key: Callable[[T], Position], descending: bool = False, queried: bool = False) -> KeysetPage[T]

    The page of items that params asks for, in the list's order whichever the direction.

    Parameters:

    Name Type Description Default
    key Callable[[T], Position]

    an item's sort key: a unique value or tuple ((p.price, p.id), not p.price alone, which two items may share).

    		 required
    descending bool

    the list goes from the greatest key to the smallest (newest first).

    		 False
    queried bool

    items is what the database returned for this page: up to params.fetch rows past params.after, in the list's order; or with params.before, the rows before it in the reverse order, nearest first (ORDER BY key DESC for an ascending list), which paginate puts back in order. The extra row tells whether there's another page that way; the other way, a page reached by a key takes there to be one, the page it came from. Otherwise items is the whole list, sorted by key, and the page is found in it.

    		 False

    fastapi_alcazaba.pagination.id_based.PaginationIdBased ¶

    PaginationIdBased(id_type: type[Id] = int, *, default_limit: int = 50, max_limit: int = 100)

    Pagination by id: ?limit=20, then ?last_id=<last_id>&limit=20.

    ids = PaginationIdBased()

@app.get("/messages")
@cache(expire=60)
async def messages(
    params: Annotated[IdBasedParams, Depends(ids)],
) -> IdBasedPage[Message]:
    rows = ...  # WHERE id > params.last_id ORDER BY id LIMIT params.fetch
    return ids.paginate(rows, params, key=lambda m: m.id, queried=True)

    The id travels as it is, neither encoded nor signed: ids are public, and clients that keep the last one they've seen can ask for whatever came after it. To sort by other columns, or keep the sort key from clients: PaginationCursor.

    Parameters:

    Name Type Description Default
    id_type type[Id]

    the type of the ids, and of the query parameter: int, str or UUID. A last_id of another type is a 422.

    		 int
    default_limit int

    items per page when the request doesn't say.

    		 50
    max_limit int

    the most a request may ask for (a 422 beyond).

    		 100

    params ¶

    params(*, last_id: Id | None = None, limit: int | None = None) -> IdBasedParams

    The parameters of a page, as the dependency gives them (for tests and scripts).

    paginate ¶

    paginate(items: Sequence[T], params: IdBasedParams, *, key: Callable[[T], Id], descending: bool = False, queried: bool = False) -> IdBasedPage[T]

    The page of items that params asks for, linked to the first and next pages.

    Parameters:

    Name Type Description Default
    key Callable[[T], Id]

    an item's id, unique.

    		 required
    descending bool

    items go from the greatest id to the smallest (newest first), and each page holds the items whose id is smaller than last_id.

    		 False
    queried bool

    items is what the database returned for this page: up to params.fetch rows with an id past params.last_id, in order (WHERE id > :last_id ORDER BY id LIMIT :fetch). Otherwise items is the whole list, sorted by id, and the page is found in it.

    		 False

    fastapi_alcazaba.pagination.time_based.PaginationTimeBased ¶

    PaginationTimeBased(direction: Direction = 'older', *, default_limit: int = 50, max_limit: int = 100)

    Pagination by time: ?limit=20, then ?timestamp=<next_timestamp>&limit=20.

    feed = PaginationTimeBased()  # older, newest first

@app.get("/posts")
@cache(expire=60)
async def posts(params: Annotated[TimeBasedParams, Depends(feed)]) -> TimeBasedPage[Post]:
    rows = ...  # WHERE posted_at < params.timestamp ORDER BY posted_at DESC
    #             LIMIT params.fetch
    return feed.paginate(rows, params, time=lambda p: p.posted_at, queried=True)

    The timestamp is plain ISO 8601, with a time zone (a 422 without one): clients read it, and may as well send one of their own (the posts before yesterday). The next page starts past the time of a page's last item, so a page never splits the items that share a time: with the whole list, paginate takes the rest of them into the page; with queried rows, it leaves them all to the next one.

    Parameters:

    Name Type Description Default
    direction Direction

    "older" for the items before the timestamp, newest first (feeds), or "newer" for those after it, oldest first (syncing).

    		 'older'
    default_limit int

    items per page when the request doesn't say.

    		 50
    max_limit int

    the most a request may ask for (a 422 beyond).

    		 100

    params ¶

    params(*, timestamp: datetime | None = None, limit: int | None = None) -> TimeBasedParams

    The parameters of a page, as the dependency gives them (for tests and scripts), with the timestamp in UTC: one cache entry per instant, whatever the offset it came with. Raises ValueError if the timestamp has no time zone.

    paginate ¶

    paginate(items: Sequence[T], params: TimeBasedParams, *, time: Callable[[T], datetime], queried: bool = False) -> TimeBasedPage[T]

    The page of items that params asks for, never splitting the items that share a time.

    Parameters:

    Name Type Description Default
    time Callable[[T], datetime]

    an item's time, with a time zone.

    		 required
    queried bool

    items is what the database returned for this page: up to params.fetch rows with a time past params.timestamp, in order (WHERE t < :timestamp ORDER BY t DESC for "older", WHERE t > :timestamp ORDER BY t for "newer"). When the extra row shares its time with the last ones, those are left to the next page; when that leaves none, more than limit items share one time and a ValueError says to paginate by a unique key (PaginationKeyset). Otherwise items is the whole list, newest first ("older") or oldest first ("newer"), and the page takes the rest of the items that share its last time, past limit if need be.

    		 False

    fastapi_alcazaba.pagination.search_after.PaginationSearchAfter ¶

    PaginationSearchAfter(sort: Sequence[type[CursorValue]], *, default_limit: int = 50, max_limit: int = 100)

    Pagination after the sort values of the last item seen: ?search_after=["2026-10-29T10:00:00Z",42]&limit=20.

    events = PaginationSearchAfter(sort=(datetime, int))

@app.get("/events")
@cache(expire=60)
async def list_events(
    params: Annotated[SearchAfterParams, Depends(events)],
) -> SearchAfterPage[Event]:
    rows = ...  # WHERE (created_at, id) > params.search_after ... LIMIT params.fetch
    return events.paginate(rows, params, key=lambda e: (e.created_at, e.id), queried=True)

    The values are plain JSON that clients read and may write: the page gives the last item's as search_after, and a client can as well start after values of its own (the events after a date). They're neither encoded nor signed, so sort by what clients may see. Each is converted to the type sort declares, and a value of another type, another number of them or JSON that doesn't parse is a 400, before the endpoint runs.

    Parameters:

    Name Type Description Default
    sort Sequence[type[CursorValue]]

    the types of the sort values, in order: int, float, str, bool, datetime (with a time zone), date, UUID or Decimal. In JSON they're as the items show them: datetimes and dates in ISO 8601, UUIDs and decimals as strings (which keep every digit of a decimal), the rest as themselves.

    		 required
    default_limit int

    items per page when the request doesn't say.

    		 50
    max_limit int

    the most a request may ask for (a 422 beyond).

    		 100

    params ¶

    params(*, search_after: str | None = None, limit: int | None = None) -> SearchAfterParams

    The parameters of a page, with search_after (JSON) converted, as the dependency gives them. Raises an HTTPException (400) if it isn't valid.

    decode ¶

    decode(search_after: str) -> tuple[CursorValue, ...]

    The sort values in search_after, a JSON array, converted to the types of sort. Raises an HTTPException (400) if they aren't those.

    paginate ¶

    paginate(items: Sequence[T], params: SearchAfterParams, *, key: Callable[[T], tuple[CursorValue, ...]], descending: bool = False, queried: bool = False) -> SearchAfterPage[T]

    The page of items that params asks for.

    Parameters:

    Name Type Description Default
    key Callable[[T], tuple[CursorValue, ...]]

    an item's sort values, of the types of sort: unique together ((e.created_at, e.id), not (e.created_at,) alone, which two items may share).

    		 required
    descending bool

    items go from the greatest key to the smallest (newest first).

    		 False
    queried bool

    items is what the database returned for this page: up to params.fetch rows with a key past params.search_after, in order. Otherwise items is the whole list, sorted by key, and the page is found in it.

    		 False

    fastapi_alcazaba.pagination.page_token.PaginationToken ¶

    PaginationToken(secret: Secrets, *, ttl: int = 3600, default_page_size: int = 50, max_page_size: int = 100)

    Pagination by page token: ?page_size=20, then ?page_size=20&page_token=<token>.

    tokens = PaginationToken(settings.page_token_secret)

@app.get("/books")
async def books(
    params: Annotated[TokenParams, Depends(tokens)],
    genre: Genre | None = None,
) -> TokenPage[Book]:
    rows = ...  # WHERE genre = :genre ... LIMIT params.fetch OFFSET params.offset
    return tokens.paginate(rows, params, queried=True)

    A page token holds where the next page starts, a digest of the request's other query parameters and when it was issued, signed with HMAC-SHA256. A token that a client made or changed, that comes with other query parameters than the ones it was issued for (the next page of genre=poetry asked with genre=novel), or that is older than ttl, is a 400 before the endpoint runs. page_size may change from one page to the next. Tokens are base64, not encrypted: a client can read the offset in them.

@app.get("/orders/export")
async def export(params: Annotated[ScrollParams, Depends(scroll)]) -> ScrollPage[Order]:
    if params.scroll_id is None:
        return await scroll.start(await find_orders(), params)
    return await scroll.next(params)

    The batches are what was found when the scroll started, whatever is written meanwhile. The snapshot lasts keep_alive seconds after each batch; once it has expired, its scroll_id is a 404 and the client starts again. A scroll_id is signed (HMAC-SHA256) and holds the snapshot's id and where the next batch starts, so a retried request gets the same batch.

    The snapshot is one entry under Cache.state_key, which the cache's clear() leaves alone, in the shared tier of a TieredBackend, and sealed with the cache's signing_key or encryption_key (the latter when it holds personal data). Whoever has a scroll_id reads the rest of the snapshot without the endpoint's query running again: when the results depend on who asks, pass owner (the user's id) to start and next, and a scroll_id is only good for them. Each batch reads the whole snapshot from the backend and writes it back to renew it: keep max_items modest.
